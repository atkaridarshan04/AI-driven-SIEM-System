# V2.0 Project Structure

> Canonical layout for the V2.0 rewrite. Every path below is intentional.
> Derived from the V1.5 codebase + improvements.md + future.md.

---

## On the "separate network model" question

There is no separate network model in V2.0 or any planned version.

The original two-model idea (one for logs, one for network) was superseded by the
`SemanticLogTransformer` design: a single model that embeds any log source — syslog,
auth, process, network flows, DNS, CloudTrail — into a shared vector space using
`sentence-transformers/all-MiniLM-L6-v2`. Network data (LANL `flows.txt`, `dns.txt`)
is just another ingestion source. No separate training, no separate inference path.

Cross-source correlation (linking a network anomaly to an auth anomaly on the same host)
is handled by the V3.0 incident correlator, not by a second model.

## Key Structural Decisions

### LSTM_AE/ → transformer/
The entire `LSTM_AE/` directory is replaced by `transformer/`. The new module keeps the
same interface (`detector.py`, `preprocessor.py`, `severity.py`, `classifier.py`) so
`pipeline.py` changes are minimal — swap the import path and update artifact filenames.

### parsers/ replaces the single parse.py dispatch
V1.5 had one `parse.py` that called Brain for everything. V2.0 adds Windows EVTX and
LANL sources. Each source gets its own parser module that normalizes output to the same
column schema (`EventTemplate`, `Content`, `Level`, `Component`, `Time`) so the pipeline
is source-agnostic downstream.

### serving/ — FastAPI replaces push-to-Express
V1.5 pushed results to Express after a batch run. V2.0 wraps the pipeline in a FastAPI
service. Express (and any other consumer) calls `/predict` instead. The `express_exporter.py`
push pattern is kept as a fallback during transition but is deprecated.

### infrastructure/ — observability as code
Elasticsearch replaces MongoDB for log storage. Prometheus replaces the custom
`/api/system-health` endpoint. Grafana replaces Chart.js panels. All configs are
version-controlled under `infrastructure/` and provisioned automatically via
docker-compose volume mounts.

### No separate network model — ever
Network sources (LANL flows/dns, firewall syslogs, NetFlow) are normalized by their
respective parser in `parsers/`, embedded by the same `SemanticLogTransformer`, and
processed by the same `AnomalyDetectionPipeline`. Cross-source correlation is a V3.0
concern handled by a separate correlator service, not a second model.

## Artifact Filenames (V2.0)

| File | Produced by | Consumed by |
|------|-------------|-------------|
| `semantic_transformer.pth` | `transformer/train.py` | `transformer/detector.py` |
| `semantic_artifacts.pkl` | `transformer/train.py` | `transformer/preprocessor.py`, `pipeline.py` |

V1.5 artifacts (`final_lstm_sequential.pth`, `hybrid_ensemble_artifacts.pkl`) are
incompatible with V2.0 — retrain from scratch on LANL data.

## Environment Variables (complete list)

```bash
# Kafka
KAFKA_HOST=localhost

# MongoDB (Express backend — kept during transition)
MONGO_URI=mongodb://localhost:27017/siem

# Express
API_KEY=<generate with openssl rand -hex 32>
PORT=5000

# Frontend
NEXT_PUBLIC_API_URL=http://localhost:5000

# Elasticsearch
ELASTIC_PASSWORD=<set on first boot>

# Model serving
MODEL_ARTIFACTS_PATH=artifacts/
FASTAPI_PORT=8000
```

All of the above must be documented in `.env.example` at the repo root.
